# Data dictionary

Schemas for the CSVs regenerated by `notebooks/02-analysis-and-charts.ipynb` (via `scripts/`)
from the per-model JSON under `results/<model>/`.

## Metrics

- **ER**: Execution Rate: the generated SQL runs without error (runnable). *Not* the BIRD leaderboard's "EX".
- **BEX**: BIRD Execution Accuracy: strict set-equality of the result set vs the gold set (what the BIRD leaderboard reports as "EX").
- **VM**: Value Match: predicted values match gold within tolerance.
- **Soft-F1**: partial-overlap F1 between predicted and gold result sets.
- **`gap_pp` = ER − BEX** (percentage points): the diagnostic: a query can run yet not answer the question. A large gap means runnable-but-wrong SQL.

## `all-results.csv` (one row per model × condition × database)

| Column | Meaning |
|---|---|
| `model` | short code (`9B`, `27B`, `30B`, `QWEN36`, `GEMMA4`, `OPUS47`) |
| `model_full` | full name + version (e.g. `Qwen3.5-9B`, `Qwen3-Coder-30B-A3B-Instruct`, `Claude Opus 4.7`) |
| `database` | one of the 11 BIRD mini-dev databases |
| `level` | condition (see below) |
| `cases` | number of questions in the cell |
| `er_pct` | Execution Rate % |
| `bex_pct` | BIRD Execution Accuracy % (BEX) |
| `vm_pct` | Value Match % |
| `soft_f1` | mean Soft-F1 |
| `gap_pp` | **ER − BEX** (pp): the canonical gap |
| `errors` | count of cases with an error status |
| `simple_er` / `moderate_er` / `challenging_er` | ER % by BIRD difficulty |
| `simple_bex` / `moderate_bex` / `challenging_bex` | BEX % by BIRD difficulty |

## Conditions (`level`)

- **L0–L4**: cumulative metadata ladder: L0 bare schema; +Data Dictionary, +Query Patterns, +Business Context, +Domain Knowledge.
- **L0-PAD**: token-matched control (L0 padded with irrelevant text to the L4 token budget).
- **L4-DD / L4-QP / L4-BC / L4-DK**: leave-one-out (full metadata minus one dimension).
- **EVIDENCE**: BIRD's built-in per-question hints baseline.

## `semantic-errors.csv` (value-incorrect cases, from `semantic_error_taxonomy.py`)

| Column | Meaning |
|---|---|
| `model`, `database`, `level` | provenance of the failing case |
| `question_id` | question identifier / index |
| `status` | operational status (ok, execution_error, parse_error, …) |
| `execution_success` | whether the SQL executed |
| `gold_sql`, `predicted_sql` | the gold vs generated SQL |
| `category` | failure mode ∈ {wrong_join, wrong_aggregation, wrong_value_literal, wrong_casing, missing_group_by, wrong_table, wrong_ordering_limit, semantically_equivalent} (heuristic first-pass; review by hand) |
